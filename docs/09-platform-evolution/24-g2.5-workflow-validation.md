## 2. Buyer workflow

```text
Listing (APPROVED)
  → Checkout (single listing — no cart)
  → Pricing snapshot (Revenue Engine)
  → Payment sim (Telebirr / CBE Birr)
  → PAID_ESCROW
  → [Admin START_FULFILLMENT]  ← required handoff
  → Courier assignment / execution
  → DELIVERED
  → Buyer confirmation
  → COMPLETED + stub settlement intents
```

| Step | Status | Notes |
|------|--------|-------|
| Browse / search | **Pass** | Public listings require `moderationStatus=APPROVED` |
| Cart | **N/A / Missing** | Single-listing checkout only — acceptable for RC1 |
| Checkout | **Pass** | `POST /orders` |
| Pricing | **Pass** | Server snapshot; Payment uses `payment.amount` = `buyerChargeEtb` |
| Payment | **Pass** | Simulated PIN → `confirm-payment` → escrow |
| Farmer acceptance | **Missing** | No accept API; farmer may decline only while `PENDING_PAYMENT` |
| Courier assignment | **Partial** | Not automatic on payment; Admin creates shipment then assigns |
| Delivery | **Pass** | Full courier status machine once assigned |
| Confirmation | **Pass** | `confirm-delivery` / shipment path |
| Settlement | **Partial** | Accruals + payment-intent stubs; no live rails |

### Order state transitions (confirmed)

| From | Trigger | To |
|------|---------|-----|
| — | createOrder | `PENDING_PAYMENT` |
| `PENDING_PAYMENT` | buyer confirmPayment | `PAID_ESCROW` |
| `PENDING_PAYMENT` | buyer cancel / farmer decline | `CANCELLED` |
| `PAID_ESCROW` | Admin START_FULFILLMENT | `CONFIRMED` (+ shipment create) |
| `CONFIRMED` | Admin MARK_SHIPPED | `SHIPPED` |
| `SHIPPED`/`CONFIRMED` | Admin MARK_DELIVERED | `DELIVERED` |
| `DELIVERED` (shipment) | buyer confirm | `COMPLETED` |
| * | raise dispute | `DISPUTED` |

**Escrow:** `PAID_ESCROW` is the accounting hold; capture is simulated (`BUYER_CAPTURE` intent).

## 4. Courier workflow

| Step | Status | Notes |
|------|--------|-------|
| Available | **Pass** | Courier availability flag |
| Assignment | **Pass** | Admin release → assign (scalable later via auto-dispatch) |
| Accept / reject | **Pass** | Courier app + rules |
| Pickup → in transit → arrived → delivered | **Pass** | `execution.rules` + POD gate |
| Settlement | **Partial** | Earnings ledger; live payout deferred |

### Shipment status machine (validated)

```text
CREATED → AWAITING_ASSIGNMENT → ASSIGNED → ACCEPTED
  → PICKED_UP → IN_TRANSIT → ARRIVED → DELIVERED
  → BUYER_CONFIRMED → COMPLETED
(+ CANCELLED / FAILED / RETURNED branches)
```

**Scalability:** Assignment is Admin-first by design (RC1). Future auto-dispatch can subscribe to `AWAITING_ASSIGNMENT` without changing the status model.
